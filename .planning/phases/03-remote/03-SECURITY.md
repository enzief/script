## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| shell environment → script 1 | `REMOTE_NAME`/`REMOTE_PATH` arrive from the process environment and are interpolated into the remote spec passed to `rclone` | remote alias/path config |
| MEGA remote → local filesystem | Every `.Path` value in the `rclone lsjson` manifest becomes a component of a local destination path the script creates and moves a file into | remote-controlled path segments |
| repository → git history | Remote name/path were previously committed as plaintext literals in a tracked file (now removed) | config literals (historical) |
| test fixture → PATH | The suite prepends a fixture-owned directory containing a stub `rclone` to PATH for the duration of each invocation | executable resolution |
| shadow file → script 2 | Each shadow file is `source`d, so its contents execute as zsh in the script's own shell; the two variables it sets become a read path and an absolute `mv` destination | file paths |
| shadow file → local filesystem | `ORIGINAL_LOCAL_PATH` is used verbatim as an absolute `mv` destination, anywhere the invoking user can write | absolute filesystem path |
| test fixture → script 2 | The suite hand-writes shadow files and feeds them to the script, which sources them | file paths |

**Auditor notes (non-blocking):**
- **Unregistered flag — no `--` argument terminator on the rclone call** (`rename-remote-files-1-match-remote.zsh:37`). `REMOTE_NAME`/`REMOTE_PATH` became environment-sourced inputs this phase; a value starting with `-` would be parsed by `rclone` as a flag rather than a remote spec. No threat ID covers argument injection specifically — flagged for a future phase, not minted retroactively (register is plan-time authoritative). Same trust basis as T-03-01/T-03-02 (user supplies their own env vars).
- **T-03-05 residual**: the regression guard that proves the `unset` fix (position-independence scenario) depends on `find` traversal order visiting a valid shadow file before the malformed one in the test fixture. The mitigation itself is present and correct in the code; this is a durability note on the *test*, not a gap in the fix.
- `03-02-SUMMARY.md` understates its own regression-guard evidence (describes it as a manual-only procedure); the auditor independently reproduced it as a persistent, suite-enforced regression check. Documentation is more conservative than reality.
- Cosmetic: both plans' acceptance criteria expect `grep -c 'mktemp -d'` = 1; actual is 2 (second hit is inside an error-message string, not a second fixture root). The underlying security property (single `mktemp -d`-derived root) holds.
