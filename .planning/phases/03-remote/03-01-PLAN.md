<environment_finding>
**REMOTE-01's diagnosed bug does not exist. Verified empirically during planning, per D-01.**

`.planning/codebase/CONCERNS.md` line 20 asserts that `remote_map` is populated in the parent
shell and then read inside a `find … | while` *subshell*, so "line 45 will always return false
… resulting in 'No Match' for every file. The entire matching logic fails." That is a bash
premise. In zsh the **last** element of a pipeline runs in the current shell, so the loop body
shares the parent's variables. Three checks on this machine (zsh 5.9):

1. A minimal reproduction of the exact loop shape read a pre-populated associative array
   inside the loop and printed `Match Found` for every seeded size.
2. The same loop *wrote* a new key inside its body which was still visible after `done` —
   decisive proof the body is not a subshell.
3. The unmodified `rename-remote-files-1-match-remote.zsh` was run against a fixture source
   tree with a stubbed `rclone` on PATH. It printed
   `Match Found (Size: 11): a.jpg -> alpha.jpg` and
   `Match Found (Size: 22): sub/b jpg with space.jpg -> beta.jpg`, wrote both shadow files,
   moved both files into the sync tree, and left the one non-matching file alone.
   `rename-remote-files-2-rename-local.zsh` then reverted both back to their original paths.

So ROADMAP Phase 3 success criterion 1 is **already TRUE before any code change**, exactly as
happened with LOCALFS-01 and LOCALFS-02 in Phase 1. Per D-01 the loop conversion in Task 1
therefore ships as **hardening for consistency with `dev/local-filesys/`, not as a bug fix**,
and the real deliverable for REMOTE-01 is the regression test that would have caught this
claim in seconds.

No defect was found in the `rclone`/`jq` output parsing either — the `jq` filter selects
non-directory entries and emits `Size Path` pairs that index correctly.

**Both `rclone` (v1.73.5) and `jq` (1.8.1) are installed on this machine.** The dependency
checks therefore cannot be tested by simply not having the tools; the suite must synthesize
their absence by controlling PATH. The round-trip harness stubs `rclone` (so no real remote is
ever contacted) but uses the **real `jq`**, which is what makes the manifest-parsing path
genuinely covered rather than mocked away.
</environment_finding>
