<objective>
**User story:** **As** the person running `retain-dir-struct-2-sorted.zsh`, **I want to** preview exactly which shadow files it would copy before it touches anything, and to have its hash-matching behaviour locked by a runnable test, **so that** a script which really does move data on my disk can be trusted and cannot silently regress.

Deliver one complete vertical slice: `retain-dir-struct-2-sorted.zsh` fully finished — loop form hardened, output standardized on `print`, `--dry-run` added — plus the tracked test file that proves it works and will catch a regression.

**Read this before starting — the requirement text is based on a misdiagnosis.**

`LOCALFS-01`, `CONCERNS.md`, and `CONTEXT.md` D-01 all state that `shadow_map` lookups "silently return empty" because the `find | while` loop runs in a subshell. **That is false for zsh.** Unlike bash and POSIX sh, zsh runs the *last* element of a pipeline in the **current** shell, so the loop is not a subshell at all: reads succeed, writes persist, and `exit` inside the loop terminates the script. Verified against zsh 5.9 by running the real scripts end-to-end: matching already succeeds today and `cp` already runs. The analysis applied bash semantics to zsh scripts.

Therefore this task is **hardening, not a bug fix**, and the plan must not describe it as fixing broken behaviour. The conversion is still worth doing for one concrete reason: the current code is correct *only* because of that non-obvious zsh guarantee, and it silently breaks the moment anyone appends another stage to the pipeline (the loop stops being last) or ports the script to bash. Process substitution makes the correctness local and obvious, and matches the sibling loop already in this same file.

Purpose: make script 2 safe to run for real, and pin its behaviour so a future "fix" for the phantom bug cannot break it.
Output: hardened `retain-dir-struct-2-sorted.zsh` with a `--dry-run` flag, and `dev/local-filesys/tests/test-retain-dir-struct.zsh`.
</objective>

A bare `print "-----..."` parses the leading dashes as option flags and **prints nothing at all, silently, with exit status 0** — confirmed on zsh 5.9. The `--` terminator is mandatory for them. ## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem → script | Directory and file **names** discovered by `find` are untrusted input; they flow into `cp`, `mkdir -p`, and output formatting |
| file content → script | Shadow `.txt` contents are parsed by `awk` and the extracted hash becomes an associative-array key |
| operator argv → script | The three positional directory paths and the new `--dry-run` flag |
