<objective>
Make image-dimension-detection failures in `dev/manga/number-pages.zsh` visibly explicit
instead of silently absorbed, and lock the behavior in with the first tracked test for
`dev/manga/`.

Purpose: `identify` silently returning nothing is currently reported as a `Warning`-level
line buried in a stream of rename output, with no trace in the closing summary. A user
renumbering a 200-page chapter has no way to notice that three pages were guessed rather
than measured — and a guessed double-page is a silently misnumbered chapter. Making the
failure loud and counting it in the summary closes that gap without touching the control
flow the user relies on (D-01, D-04).

Output: `dev/manga/number-pages.zsh` with an `Error:`-prefixed non-fatal failure message and
a `dim_failures` counter surfaced in the summary line, plus a new
`dev/manga/tests/test-number-pages.zsh` regression test that runs hermetically without
ImageMagick installed.

`**Goal:**` line for Phase 2 ("`manga` scripts remain reliable and handle image-dimension
detection failures explicitly") is not in `As a / I want to / so that` form. Per the MVP
planning rules the planner must surface this rather than invent a story. Run
`/gsd mvp-phase 2` if a user story is wanted before execution; the phase is otherwise fully
specified by `02-CONTEXT.md` and does not block on it.
</objective>

<environment_finding>
**ImageMagick is NOT installed on this machine.** Verified during planning:
`identify`, `convert`, and `magick` are all absent from PATH. `number-pages.zsh` exits 1 at
its dependency check (line 67) when `identify` is missing, so a test that depends on real
ImageMagick cannot run here at all, and a test that skips when ImageMagick is absent would
never execute on the developer's own machine.

The test therefore supplies its own `identify` stub on PATH. This was prototyped against the
unmodified script during planning and confirmed working: the stub drove the empty-dims
branch, the single-page branch, and the double-page branch, and the script exited 0. The
stub is also strictly more precise than real ImageMagick for this requirement — D-03 scopes
detection to "`identify` produced empty stdout", which the stub reproduces exactly and
deterministically, with no dependency on which formats a given ImageMagick build supports.

**Accepted limitation, recorded deliberately:** because the stub models `identify`'s output
contract rather than `identify` itself, the test does not prove what real ImageMagick emits
on a genuinely corrupt file. That is in-scope-by-omission per D-03, which explicitly declines
to check `identify`'s exit code this phase.
</environment_finding>
