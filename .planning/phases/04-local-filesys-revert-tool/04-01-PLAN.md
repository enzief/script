<objective>
Create `dev/local-filesys/retain-dir-struct-4-revert.zsh` — a single bidirectional
script that swaps a hash-only `.txt` shadow with its real file — and the tracked
regression suite that proves it. Wave 1 delivers the whole swap path end-to-end
(name-first resolution, mandatory hash verification, the two-`mv` positional
exchange) and then makes every failure mode explicit and non-destructive.

**Architecture choice (CONTEXT.md Claude's Discretion):** one script, not two.
D-08 states `revert-revert` is not a separately-designed operation — it is the
identical swap with the two tree roles reversed. Two scripts would duplicate the
entire matching-and-swap core for zero behavioural difference, which the project's
"no speculative abstraction" constraint rules out. The bidirectionality is
expressed in the argument order: the first argument is always the tree whose
shadows are being resolved.

Purpose: closes the gap the `retain-dir-struct-*.zsh` pipeline has always had —
scripts 1, 2 and 3 read and index real data but never relocate it. This is the
first script in the family that moves real user files, so every failure mode
errors out rather than guessing (D-05).

Output: a working, tested `revert` direction. Plan 04-02 adds `--dry-run` (D-09)
and proves the reverse direction round-trips (D-08).
</objective>

**Argument handling and validation.** Exit 1 with a stderr usage line when fewer than two
arguments are given. Assign `SHADOW_TREE=${1%/}`, `shift`, then build `TARGET_TREES` from the
remaining arguments with one trailing slash stripped from each. Error to stderr and exit 1 if

**What counts as a shadow.** Enumerate candidate shadows with
`find "$SHADOW_TREE" -type f -name "*.txt" -print0`, then apply a content discriminator: read the
first field of the first line with `awk` (the `awk '{print $1}' "$shadow"` idiom from script 3
line 39, narrowed to the first line) and accept the file as a shadow only when that field matches
the 64-character lowercase hex pattern — reuse the `[[ "$x" =~ '^[0-9a-f]{64}$' ]]` form already
used at `tests/test-retain-dir-struct.zsh` line 301. This discriminator is mandatory, not
defensive polish: in this project a tree legitimately contains real `.txt` data files
(`test-retain-dir-struct.zsh` fixtures are all `.txt`), and without it the tool would treat
`notes.txt` as a shadow for a file named `notes`. Anything that fails the discriminator is left
strictly untouched; increment `nonshadow_count` and `continue`. Note `find -type f` matches
regular files only, so symlinks are never enumerated as shadows or as candidates — keep it that
way; broader symlink and permission validation is deferred requirement LOCALFS-04.

**Name index over the target trees.** Build it in one pass before the shadow loop, mirroring the
`declare -A` index pattern in `retain-dir-struct-3-find-sorted.zsh` lines 22-30 but keyed by
basename rather than hash. For every regular file across all target trees, increment
`name_count[$base]` where `base` is the file's basename (`${f:t}`), and record the first
occurrence's `realpath --` in `name_first[$base]`. Index by basename, not by relative path: after
a swap the shadow sits at the real file's old position and the real file at the shadow's old
position, so the two trees deliberately do not share relative paths — the basename is the only
stable link (D-01 stores no location metadata). Build the index by iterating the target trees
rather than shelling out to `find -name` per shadow, so a basename containing glob metacharacters
such as `*`, `?` or `[` is compared literally instead of being interpreted as a pattern.

**Per-shadow resolution.** For each accepted shadow compute `shadow_rel="${shadow#$SHADOW_TREE/}"`,
`base` as the shadow's basename with the `.txt` suffix stripped, and `dest_real="${shadow%.txt}"`
— the path the real file must land on. Branch on `${name_count[$base]:-0}`:

- Zero candidates (D-06): print a `No matching file found for: ` line naming `shadow_rel` to
  stdout, increment `skip_count`, and continue. This is not fatal; it mirrors
  `retain-dir-struct-3-find-sorted.zsh`'s existing no-match convention.
- Exactly one candidate: set `real_src="${name_first[$base]}"` and verify its hash (below).
- More than one candidate: in this task only, treat it as an error — print
  `Error: ambiguous match for ` naming `shadow_rel` and the candidate count to stderr, increment
  `error_count`, and continue. Task 2 refines this branch so a collision that only one candidate's
  hash matches resolves instead of failing. Erring on the side of refusing is the correct
  intermediate state; silently picking one is not.

**Mandatory hash verification (D-04).** Even on a unique name match, compute the candidate's hash
with `sha256sum "$real_src" | awk '{print $1}'` and compare it to the shadow's stored hash. On
mismatch, print `Error: hash mismatch for ` naming `shadow_rel` and the rejected candidate path to
stderr, increment `error_count`, and continue — a mismatch is treated exactly like a failed match
(D-05), never as a reason to move anyway.

**The swap (D-07).** Compute `dest_shadow="${real_src}.txt"`. Both destination parent directories
necessarily already exist — the shadow's parent currently holds the shadow, and the real file's
parent currently holds the real file — so no `mkdir -p` is needed anywhere in the swap; if you
find yourself wanting one, the path derivation is wrong. Guard both destinations first: if
`dest_real` or `dest_shadow` already exists, print `Error: destination already exists for `
naming `shadow_rel` and the occupied path to stderr, increment `error_count`, and continue
without moving anything. Then run exactly two moves in this order: `mv -- "$real_src" "$dest_real"`
followed by `mv -- "$shadow" "$dest_shadow"`. Real file first: it is the valuable payload, and
moving it first guarantees the shadow's destination is provably vacant. Never pass `-f` (it would
overwrite user data) and never pass `-n` (GNU `mv -n` refuses silently and still exits 0, hiding
the failure) — the explicit existence guard is the only clobber protection. The shadow is moved
byte-for-byte; do not delete-and-rewrite it and do not recompute its hash (D-01, D-07). On
success print a `Swapped: ` line naming `shadow_rel` and `real_src`, and increment `swap_count`.
Rollback of a failed second move is Task 2's scope.

**Output framing.** Follow the family's shape: a header line naming the shadow tree and the
