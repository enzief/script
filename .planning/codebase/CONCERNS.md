# Codebase Concerns

**Analysis Date:** 2026-08-05

## Tech Debt

**Subshell Variable Scope in retain-dir-struct-2-sorted.zsh:**
- Issue: Associative array `shadow_map` is declared and populated in a process substitution subshell (line 28-28), then accessed in a separate `find ... | while` subshell (line 34-53). The array will not be visible in the second subshell, causing lookups to always fail.
- Files: `dev/local-filesys/retain-dir-struct-2-sorted.zsh`
- Impact: The script's core functionality is broken — it will never find matches because `shadow_map` is empty in the subshell where it's used.
- Fix approach: Use a temporary file to store the shadow map data, or refactor to avoid multiple subshells. Zsh's process substitution (< <(...)) can be used to avoid subshells entirely.

**Subshell Variable Scope in retain-dir-struct-3-find-sorted.zsh:**
- Issue: Associative array `file_map` is populated in the parent shell (line 25-30), then accessed in a `find ... | while` subshell (line 36-50). The array will not be visible in the subshell.
- Files: `dev/local-filesys/retain-dir-struct-3-find-sorted.zsh`
- Impact: Line 42 lookups of `${file_map[$stored_hash]}` will always be empty, making all "No matching file found" results incorrect or always empty.
- Fix approach: Refactor to use process substitution instead of pipe to while loop to keep both operations in the parent shell context.

**Subshell Variable Scope in rename-remote-files-1-match-remote.zsh:**
- Issue: Associative array `remote_map` is populated in the parent shell (line 28-33), then accessed in a `find ... | while` subshell (line 38-70). The array will not be visible in the subshell.
- Files: `dev/remote/rename-remote-files-1-match-remote.zsh`
- Impact: Line 45 will always return false because `remote_map` is empty in the subshell, resulting in "No Match" for every file. The entire matching logic fails.
- Fix approach: Use process substitution or temporary files to avoid subshell context loss.

**Mixed Output Commands in retain-dir-struct-1.zsh:**
- Issue: Script uses both `echo` (lines 15, 37-38) and `print` (line 32) for output. Inconsistent style.
- Files: `dev/local-filesys/retain-dir-struct-1.zsh`
- Impact: Minor — both work in zsh, but inconsistent style reduces readability.
- Fix approach: Standardize on either `echo` or `print` (zsh prefers `print`).

## Known Bugs

**Sourced Variables Not Checked in rename-remote-files-2-rename-local.zsh:**
- Symptoms: Script sources shadow files (line 21) without verifying the source succeeded or that expected variables exist. If `MATCHED_REMOTE_PATH` or `ORIGINAL_LOCAL_PATH` are unset, the file operations continue with empty values.
- Files: `dev/remote/rename-remote-files-2-rename-local.zsh`
- Trigger: Run with a malformed or empty shadow file, or a shadow file missing required variables.
- Workaround: Manually verify all shadow files are correctly formatted before running.

**Rate Limiting Sleep is Commented Out:**
- Symptoms: The 50ms sleep between file operations (line 38) is commented out. Running with thousands of files may trigger API rate limiting on MEGA.
- Files: `dev/remote/rename-remote-files-2-rename-local.zsh`
- Trigger: Use with large file counts (>500 files).
- Workaround: Manually uncomment line 38 or run in smaller batches.

## Security Considerations

**Hardcoded Remote Credentials Path Exposure:**
- Risk: Scripts reference remote paths like "mega:devicesync/2019" (hardcoded in line 5-6 of rename-remote-files-1-match-remote.zsh), which may contain sensitive path patterns or could leak remote organization structure.
- Files: `dev/remote/rename-remote-files-1-match-remote.zsh`
- Current mitigation: None — paths are visible in plaintext script.
- Recommendations: Move remote configuration (REMOTE_NAME, REMOTE_PATH) to environment variables or a config file that is git-ignored.

**Insufficient Input Validation:**
- Risk: Scripts accept directory paths without verifying they're readable/writable before processing, or that they contain expected content. Symlinks are not rejected.
- Files: All scripts
- Current mitigation: Some basic checks (e.g., line 13-14 in retain-dir-struct-3-find-sorted.zsh), but incomplete.
- Recommendations: Add explicit checks for `cd` permissions, write access, and optionally reject symlinks with `-L` in find commands.

**Source Command from File Path:**
- Risk: Line 21 in rename-remote-files-2-rename-local.zsh uses `source` on a user-controlled file path without restrictions. If the shadow file is corrupted or malicious, arbitrary commands could execute.
- Files: `dev/remote/rename-remote-files-2-rename-local.zsh`
- Current mitigation: Script assumes shadow files are generated by trusted source.
- Recommendations: Parse shadow files with `grep` or `awk` instead of `source`, or add strict validation (e.g., whitelist allowed variable names).

## Performance Bottlenecks

**Double Hashing in retain-dir-struct-2-sorted.zsh:**
- Problem: The script computes SHA256 for every file in REORG_DIR (line 37) even though the original shadow files already contain hashes. This is redundant work.
- Files: `dev/local-filesys/retain-dir-struct-2-sorted.zsh`
- Cause: Design choice to match by hash rather than trusting existing shadow files.
- Improvement path: If files in REORG_DIR are not modified, can skip re-hashing and trust the old shadow data. Add a `--trust-existing` flag to skip hashing.

**Re-hashing Entire Directory in retain-dir-struct-3-find-sorted.zsh:**
- Problem: Script builds a complete hash index of DATADIR before processing (lines 25-30), which requires hashing every file. For large directories on slow storage (exFAT noted in comment), this is very slow.
- Files: `dev/local-filesys/retain-dir-struct-3-find-sorted.zsh`
- Cause: Necessary for the lookup approach, but acknowledged as slow in comments.
- Improvement path: Add progress reporting and consider incremental indexing or caching hashes to a persistent file.

**No Parallelization:**
- Problem: All scripts process files sequentially. With thousands of files, throughput is limited.
- Files: All scripts
- Cause: Simple shell loop design — no concurrency.
- Improvement path: Use GNU parallel, xargs -P, or zsh background jobs to process batches concurrently.

## Fragile Areas

**Image Dimension Detection (number-pages.zsh):**
- Files: `dev/manga/number-pages.zsh`
- Why fragile: Script calls `identify` for every image (line 84) and fails silently if dimensions can't be read (line 85-89). ImageMagick must be installed and working. The `-format` flag must be supported.
- Safe modification: Wrap in explicit error handling; test `identify` availability before processing files.
- Test coverage: No tests exist; behavior on corrupted/unsupported image formats is untested.

**File Movement in Subshell Loops:**
- Files: `dev/remote/rename-remote-files-2-rename-local.zsh`, `dev/remote/rename-remote-files-1-match-remote.zsh`
- Why fragile: File move operations (mv) inside subshell while loops mean if the script is interrupted mid-loop, files are left in partial state. No atomic operations or rollback.
- Safe modification: Use transaction-like approach — write a list of pending operations to a file first, then apply them. Add trap handlers to clean up on interrupt.
- Test coverage: No error recovery or testing for partial failures.

**External Dependency Chain:**
- Files: `dev/remote/rename-remote-files-1-match-remote.zsh`
- Why fragile: Depends on rclone, jq, and implicit MEGA sync status. If any fail (network down, rclone not in PATH, jq parse error), script provides no diagnostics.
- Safe modification: Add explicit `command -v` checks and error messages for missing tools.
- Test coverage: No dependency checks; assume tools are available.

## Scaling Limits

**Associative Array Memory (retain-dir-struct-2-sorted.zsh, retain-dir-struct-3-find-sorted.zsh):**
- Current capacity: All dev/remote/local files stored in arrays at once.
- Limit: Zsh arrays are in-memory. With millions of files, this will exhaust RAM.
- Scaling path: Stream-process with temporary index files instead of in-memory arrays. Split into batches.

**Sequential File Processing:**
- Current capacity: ~1-10 files/sec depending on hashing speed.
- Limit: Processing 100,000 files takes hours.
- Scaling path: Implement parallel processing with xargs or GNU parallel.

## Dependencies at Risk

**rclone (dev/remote/rename-remote-files-1-match-remote.zsh):**
- Risk: No version check; script uses `lsjson --recursive` which may not exist in older versions. No fallback if rclone not found.
- Impact: Script fails with cryptic error if rclone is missing or outdated.
- Migration plan: Add `command -v rclone` check with error message. Document minimum rclone version.

**jq (dev/remote/rename-remote-files-1-match-remote.zsh):**
- Risk: No availability check. JSON parsing assumes specific output format.
- Impact: Script fails silently if jq is not installed; JSON parsing errors are not caught.
- Migration plan: Add `command -v jq` check. Add error handling for malformed JSON.

**ImageMagick / identify (dev/manga/number-pages.zsh):**
- Risk: Script checks for `identify` (line 67-70), which is good. But older versions may not support all formats (AVIF, WEBP).
- Impact: Script warns on unsupported formats but continues; may produce incorrect results for unsupported files.
- Migration plan: Keep existing check. Consider adding format-specific version checks if AVIF/WEBP support is critical.

**grep -P PCRE (list-missing-pages.zsh):**
- Risk: `-P` flag (PCRE) is not standard on BSD grep; may not be available on macOS.
- Impact: Script fails on systems without GNU grep or PCRE support.
- Migration plan: Replace with standard POSIX extended regex or use a fallback extraction method.

## Missing Critical Features

**No Dry-Run / Preview Mode:**
- Problem: Scripts that move files (rename-remote-files-*.zsh) have no preview of what will happen. Running with wrong arguments causes data movement with no undo.
- Blocks: Safe testing and validation before commit.

**No Rollback Capability:**
- Problem: If rename-remote-files-1-match-remote.zsh fails mid-run, some files are moved and others aren't. No way to recover to the original state.
- Blocks: Safe recovery from errors.

**No Progress Reporting:**
- Problem: Scripts that process thousands of files provide no indication of progress, completion time, or error counts.
- Blocks: Monitoring long-running operations.

**No Configuration File Support:**
- Problem: Hardcoded paths (dev/remote/rename-remote-files-1-match-remote.zsh line 5-6) and options make reuse difficult.
- Blocks: Using scripts across different projects/environments.
