<objective>
Add `dev/remote/move-remote-files-to-match-local.zsh`: a new, independent script that reconciles a MEGA remote subtree's directory structure to match one or more local target directories, using server-side `rclone moveto` (metadata-only rename on the MEGA backend — no byte transfer, no MegaSync involvement). Remote files are matched to local candidates by size only (the MEGA backend exposes no content hash), and any size that is ambiguous on either side is skipped and reported rather than guessed.

Purpose: the user's iPhone camera-roll backup on MEGA still carries the original `DCIM/100APPLE/...` layout while the local WD-HDD mirror has been reorganized across three directories. This script makes the remote match the local layout without re-uploading or re-downloading a single byte.

Output: the new script plus a hermetic regression suite at `dev/remote/tests/test-move-remote-files-to-match-local.zsh` that drives it entirely through a stubbed `rclone`.

<design_decisions>
These were settled before planning. Do not re-litigate any of them.

**DD-01 — Size-only matching, skip on ambiguity.** `rclone lsjson --hash` was confirmed empirically to return no hash field for the MEGA backend; content hashes are unavailable without downloading. Size is therefore the only usable match key. Unlike `rename-remote-files-1-match-remote.zsh` (which accepts first-write-wins collisions per 03-CONTEXT.md D-02), this script SKIPS AND REPORTS on any size collision, on either side. The implementation must never call `rclone lsjson --hash` — it is known to return nothing useful for this backend and would be dead weight.

**DD-02 — `echo` output convention, not `print -r --`.** `dev/remote/`'s two existing scripts use `echo` for stdout and `echo ... >&2` for stderr. The `print -r --` convention belongs to `dev/local-filesys/` and must not be imported here. Every message this script emits begins with a non-dash literal prefix (`Would move: `, `Moved: `, `Skip: `, `Error: `, `Totals: `, two spaces for recap entries), so `echo`'s dash-swallowing behaviour is structurally unreachable.

**DD-03 — `--target` directories must already exist.** These are real local source-data directories, not swap destinations. A missing `--target` is a hard error and exit 1. Do NOT carry over `retain-dir-struct-4-revert-multi.zsh`'s target-auto-create behaviour, which exists for a different semantic.

**DD-04 — `REMOTE_NAME` / `REMOTE_PATH` are required env vars with no default** (03-CONTEXT.md D-06). Reuse the exact variable names and error-message wording from `rename-remote-files-1-match-remote.zsh:19-26`.

**DD-05 — Warn-and-continue on per-item `rclone` failure** (03-CONTEXT.md D-04). A failed `mkdir` or `moveto` for one file records an error and continues to the next; it never aborts the run.

**DD-06 — No `--` argument terminator on `rclone` calls.** `rename-remote-files-1-match-remote.zsh:37` calls `rclone lsjson --recursive "${REMOTE_NAME}:${REMOTE_PATH}"` with no terminator. 03-SECURITY.md's auditor note flags this as an unregistered residual under the same single-user trust basis as T-03-01/T-03-02. Mirror the existing call shape exactly rather than introducing an unverified `--` that cannot be tested against the real backend under this task's constraints. Recorded below as T-e42-05, accepted.

**DD-07 — Testing is stub-only. This is a hard constraint.** The executor MUST NOT invoke the real `rclone` binary against the real MEGA remote at any point in this task — not even a "harmless" dry run against real account data. The suite builds a fixture-owned stub `rclone`, PREPENDED to `PATH` (never appended — the real binary is installed at `~/.local/bin/rclone` and an appended stub would fall through to the network), exactly as `dev/remote/tests/test-rename-remote-files.zsh:101-121` already does. A live smoke test against a disposable remote path is a separate, human-supervised follow-up outside this task.
</design_decisions>

Add the malformed-manifest guard immediately after the lsjson exit-status check from Task 1: pipe the captured output through `echo "$REMOTE_JSON" | jq -e 'type == "array"' >/dev/null 2>&1` and on non-zero emit the not-a-JSON-array error and exit 1. Without this guard, unparseable output makes the indexing loop consume nothing and the run reports a clean zero-work result indistinguishable from an empty remote — a silent false success. An empty array must remain a valid zero-work run that exits 0.

Add the `--target` overlap guard after the existence check and after the `realpath --` resolution, before the manifest fetch: mirror `roots_overlap` and `reject_overlap` from `retain-dir-struct-4-revert-multi.zsh`, comparing every pair of resolved absolute target roots for equality or containment, and emit the overlapping-targets error with exit 1. Overlapping roots would enumerate the same file twice, double-counting it in the size index so a genuinely unique file is misreported as locally ambiguous and silently skipped, and would also make its stripped relative path depend on which root won.

Add the `${#TARGET_ROOTS[@]}` non-empty guard around the local-index `find` call if the implementation ever passes the array wholesale — an empty path-argument list makes `find` silently search the invoking shell's cwd. With DD-03's mandatory existence check the array cannot be empty here, but the per-root loop form makes the hazard structurally unreachable; prefer the per-root loop.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shell environment → script | `REMOTE_NAME` / `REMOTE_PATH` arrive from the process environment and are interpolated into every remote spec handed to `rclone` |
| MEGA remote → script | every `.Path` in the `lsjson` manifest becomes a component of a remote `mkdir` / `moveto` argument and of the occupied-destination set |
| local filesystem → script | the contents and layout of the `--target` roots determine the desired remote layout and therefore every move |
