## 4. The degraded path is the default here, and it is real

`vexp impact <fqn>` and `vexp flow <start> <end>` survive as CLI verbs even though their MCP equivalents are gated. The Investigator agent holds `Bash`, so blast-radius tracing still happens on this installation — through the CLI rather than through `get_impact_graph`/`search_logic_flow`. The agent's own prose states this is the DEFAULT path here, not an edge case, and its context-file output carries a `Blast-radius evidence: FULL | DEGRADED` line naming exactly which tools were unavailable and what replaced them whenever the evidence is not the MCP impact/flow tools themselves.

## 5. Read-only contradiction and its resolution

The Investigator's harness `tools:` allowlist grants `Write` (required to emit `adhoc_context.txt`) but excludes `Edit` and `NotebookEdit` by name. The harness therefore makes in-place modification of any existing file impossible regardless of prompt text; the residual privilege is creating or overwriting the one caller-supplied output path. This is documented in the agent file's own `<read_only_contradiction>` section as a real, partially prompt-enforced control, not a closed hole.

## 6. Manifest-confinement limitation

The Executor's `Minimal File Manifest` confinement is prompt-enforced only — the harness grants it repo-wide `Read`/`Write`/`Edit`. Nothing mechanically stops an edit outside the manifest. The compensating control is the `adhoc-platform-task` skill's clean-working-tree precondition (`git status --short` must be empty before Stage 2 dispatches), so every Stage 2 edit is diffable and revertable against a known baseline. The Executor's own `<enforcement_limitation>` section states this plainly and requires it to halt-and-report rather than widen its own scope if the manifest proves insufficient.

## 7. Git hooks

Three hooks are installed in this repository, not the one the original brief described: `pre-commit`, `post-merge`, `post-checkout`, each marked `vexp-hook-version: 3`, confirmed live by `vexp hooks check`. Each reindexes the repo and is wrapped so it cannot fail the git operation it hooks (`|| true`); none stages files. Kept by explicit user decision. Removable with `vexp hooks remove`.

## 8. The `.vexp/` decision and corrected reasoning

A root `.gitignore` (new — none existed before) ignores `.vexp/`, but not for the reason initially assumed. `vexp`'s own nested `.vexp/.gitignore` already excludes `index.db` (~5.8 MB), the WAL/SHM files, `daemon.sock`, `daemon.pid`, and logs — `git add -An .vexp/` showed only three small files (`.gitattributes`, `.gitignore`, `manifest.json`) would ever be staged. The real reason: the three hooks rewrite `manifest.json` on every commit/merge/checkout without staging it, producing permanent working-tree noise, and a committed index manifest carries no cross-machine value on a `Max repos: 1` free tier.
