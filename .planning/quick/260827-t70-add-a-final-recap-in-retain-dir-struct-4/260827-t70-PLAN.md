<design_decision>
**Recap entry format: the full inline message, verbatim.**

The task sketch suggested entries of the form `"$shadow_rel: <reason>"`. Every existing inline message interleaves `$shadow_rel` in the *middle* of the sentence (`"Error: hash mismatch for $shadow_rel (candidate: $real_src)"`), so producing a `rel: reason` shape would require splitting each of the seven messages into head/tail fragments or restating the reason in different words — precisely the drift the task forbids.

Decision: assign each message to a variable `msg`, print `"$msg"` at the existing call site (byte-identical output), and append the same `$msg` to `unresolved_shadows`. Recap lines are then `"  $msg"`. Every entry already names its shadow and its reason, so the informational goal is met with a single source of truth and zero possibility of drift.

Consequence for the executor: the seven inline `print` *statements* change shape (literal string → `"$msg"`), but the *emitted bytes* do not. The existing suite already asserts the exact inline text for the mismatch, ambiguous, destination-exists, no-match, and shadow-move-failed messages, so any accidental change of wording fails Task 2's regression gate.

**Recap stream: stdout, never stderr.** Case O in the existing suite asserts stderr is empty on a run that contains a no-match skip. Routing the recap to stderr would break that assertion — and would be wrong regardless: the recap is a summary, not a fresh diagnostic.

**Recap placement:** after the `nonshadow_count` block, before the `DRY_RUN`/`Done!` block, so the terminal status line remains the last line of output.
</design_decision>
