<planner_decisions>
Judgment calls made during planning, with rationale. Follow them; flag at the checkpoint if you disagree.

- **Filenames: kebab-case for the four scripts.** `.claude/CLAUDE.md` states the repo convention is `kebab-case.zsh`, and every existing script in `dev/` follows it. So: `backup_to_wdhdd.zsh` -> `backup-to-wdhdd.zsh`, `restore_from_wdhdd.zsh` -> `restore-from-wdhdd.zsh`, `install_essentials.sh` -> `install-essentials.sh`, `clone_clean_repos.sh` -> `clone-clean-repos.sh`. This forces a cascade: the instructions doc, and the header comments inside the scripts that name their siblings, all need updating. That cascade is in scope and is Task-level work, not optional polish.
- **Doc filename: `REINSTALL_INSTRUCTIONS.txt` stays as-is.** The repo's kebab-case rule is documented as a convention for script files; the repo's own docs (`PROJECT.md`, `ROADMAP.md`, `STATE.md`, `TESTING.md`) are uppercase. This file's job is to be conspicuous on a drive during an emergency, so the shouty name earns its keep.
- **Shebangs stay `#!/usr/bin/env zsh` / `#!/usr/bin/env bash`.** Other repo scripts use `#!/bin/zsh`, but these four run on a freshly installed foreign system where an env-based interpreter lookup is strictly safer, and the instructions invoke them with an explicit interpreter anyway. Deliberate deviation; do not normalize.
- **`confirm()` stays duplicated** across `backup-to-wdhdd.zsh` and `restore-from-wdhdd.zsh`. This repo has no shared-library/sourcing convention, and — more importantly — each script must be independently runnable from the backup drive during a reinstall when the repo does not exist on disk. A shared helper would be an extra file that must also be on the drive for either script to start. Each copy gets a one-line comment saying so.
- **No `-h`/`--help` heredoc.** These four scripts take zero arguments by design (all paths hardcoded per D-02), so argparse-style help would be inventing an interface that was never there. Instead each gets a short `Usage:` line inside its existing header comment block, plus an explicit rejection of unexpected arguments — which also closes a real trap (`zsh backup-to-wdhdd.zsh --dry-run` currently ignores the flag and performs a full real backup).
- **`set -uo pipefail` without `-e` is intentional in all four** and stays. Each is a best-effort multi-step operation where one failed step must not abandon the remaining ones: the backup's ~40 independent copies and Tier-2 `confirm()` flow, the restore's optional dirs plus its trailing permission-fix block, the installer's long apt sequence, and the cloner's 15 independent repos. Do NOT add `-e`. Each script gets a one-line comment recording that this is deliberate. The fixes below compensate by checking and reporting individual step failures explicitly instead of relying on the shell to abort.
- **Explicitly out of scope — do not "fix" these:** the `curl ... | sh` install pattern for nvm/uv/Brave (documented upstream method), the Signal `xenial` apt suite (correct — Signal publishes under xenial regardless of Ubuntu release), `GIT_SSH_COMMAND=ssh -o StrictHostKeyChecking=accept-new` (deliberate TOFU for an unattended first run), the restore's copy-not-extract handling of the four tar archives (documented intentional behavior), and the `.ssh` permission block's existing logic.
</planner_decisions>
