<objective>
Add `dev/manga/trim-borders.zsh`: the kebab-case zsh successor to the untracked `dev/manga/trim_borders.sh`. It takes a required `<dir>`, recursively trims uniform borders from jpg/jpeg/png images in place, and replaces the old bitmap round-trip plus three-processes-per-iteration loop with one `magick` process per trim iteration. It adds the safety guard the old script lacked (research Pitfall 1 reproduced the old script overwriting an 800x1200 PNG with a 1x1 JPEG), keeps each file's own format and JPEG quality, and adds `-f/--fuzz` and `-e/--edges all|v|h` options.

Purpose: these scripts overwrite real manga pages, so the replacement must never write a collapsed or wrong-format result over an original.

Output: `dev/manga/trim-borders.zsh` (executable), `dev/manga/tests/test-trim-borders.zsh` (executable regression suite on synthetic images), and `dev/manga/trim_borders.sh` deleted.

<design_decisions>
Locked user decisions. Do not re-litigate.

- **D-01 Fuzz:** `-f N` / `--fuzz N`, default `3` (percent), validated numeric before any file is touched. Decimals such as `2.5` are accepted (ImageMagick accepts them).
- **D-02 Target:** one required positional `<dir>`, processed recursively (same idea as `number-pages.zsh` taking a dir). `-h` / `--help` prints a heredoc usage in the `number-pages.zsh` layout. No default to `.`: an accidental run in the wrong cwd must not rewrite images.
- **D-03 In-place with minimum-size guard:** originals are overwritten in place, but any result that collapsed or fell under the floor is skipped: `Warning:` on stderr, original left untouched. No dry-run flag.
- **D-04 Sequential:** one image at a time, no `xargs -P`, no background jobs.
- **D-05 No bitmap intermediate; one `magick` per trim iteration** using `-write <file> -format "%w %h" info:` (research Q1, verified).
- **D-06 No black-to-white color-replacement pass.** Plain `-trim` samples the corner pixel, so black and white borders need no special branch (research Q2 verified the old replacement pass is destructive on white-content pages).
- **D-07 Preserve source format and JPEG quality:** output extension comes from `${img:e}` so a PNG stays PNG; JPEG output gets `-quality` equal to the source's `%Q`.
- **D-08 Safe iteration and temp hygiene:** `find ... -print0` with `while IFS= read -r -d ''`; temp files live in a `mktemp -d` dir or the image's own dir and are always cleaned up.
- **D-09 File:** `dev/manga/trim-borders.zsh`, `#!/bin/zsh`, executable. Delete the untracked `dev/manga/trim_borders.sh` with `rm` (it is not in git, so `git rm` does not apply).
- **D-10 Edges (added by the user after research):** `-e` / `--edges all|v|h`, default `all`. `v` (vertical) = top + bottom edges only; `h` (horizontal) = left + right edges only. `--help` must state these meanings explicitly. Implementation: ImageMagick 7's `-define trim:edges=north,south` (v) / `trim:edges=east,west` (h). Fallback if the define does not behave: compute the `%@` bounding box and crop only the selected axis. Tests: `v` leaves width unchanged, `h` leaves height unchanged, `all` trims both, on a 4-sided-border image.

Planner's discretion choices (made for this plan; executor follows them):

- **DD-01 Floor value:** `MIN_KEEP_PCT=50` as a named constant near the top of the script. The guard compares the converged result against the ORIGINAL dimensions: skip if `cw * 100 < ow * MIN_KEEP_PCT` or `ch * 100 < oh * MIN_KEEP_PCT`. Because trim sizes never grow, checking once after the loop is equivalent to checking every iteration. A skipped file keeps its original bytes entirely (D-03 "leave original untouched"); the script does not fall back to an earlier, larger iteration.
- **DD-02 Metadata is kept:** the old script's `-strip` is not carried over, and `-auto-orient` is not added. Trim removes rows/columns on all selected sides, so a crop in stored orientation is the same crop in display orientation, and keeping the EXIF orientation tag keeps viewers correct (resolves research Pitfall 3 without a new flag). `-auto-orient` would also swap w/h relative to the `identify` dims and break the no-shrink comparison on the first iteration.
- **DD-03 Intermediate format:** per-iteration results go to `$tmpdir/next.miff` / `$tmpdir/work.miff` (ImageMagick's native lossless format). JPEG intermediates would compound re-encode loss, and PNG intermediates are slow to compress.
- **DD-04 Atomic replace:** encode the final result into `$tmpdir/out.<ext>`, `cp` it to a hidden same-dir temp `${img:h}/.trim-borders.$$.<ext>`, `chmod --reference="$img"` it (the old script's `cp` over the original kept the original mode), then `mv -f` it over the original. ImageMagick never writes into the user's tree, only into the `mktemp -d` dir under controlled names, so a filename's ImageMagick-special characters never reach an output path. An interrupt can never leave a half-written original.
- **DD-05 Snapshot before mutating:** collect the full `-print0` list into an array before processing, so files created during the run are never enumerated. `find` also excludes `.trim-borders.*` (leftovers from a SIGKILLed run).
- **DD-06 Output:** `print -r --` for stdout and `print -u2 -r --` for stderr (zsh `echo` interprets backslashes in filenames). Paths in messages are relative to `<dir>` and single-quoted.
- **DD-07 Exit code:** exit 1 if any per-file `Error:` occurred (after processing every file), else 0. Guard skips are warnings and do not affect the exit code. An empty image set prints `No image files found in '<dir>'` on stderr and exits 1, matching `number-pages.zsh`.
- **DD-08 Extensions:** jpg, jpeg, png, matched case-insensitively (the old script's set).
- **DD-09 Single dependency:** only `magick` is checked; dimensions and quality are read with `magick identify`.

Facts verified by the planner at plan time (ImageMagick 7.1.2-18 Q16, zsh 5.9):

- `-define trim:edges=north,south` on an 800x1200 white page with a centered 600x900 checkerboard gives 800x900; `east,west` gives 600x1200; no define gives 600x900. Asymmetric borders (content at +50+100) trim to the correct content offset. The define works in the per-iteration `-write` / `-format` pattern, so the `%@` fallback is not needed. (Do not use `%@` with the define: it reports a +1 on the untrimmed dimension, for example `801x900`.)
- An invalid `trim:edges` value (such as `bogus`) or an empty value is silently ignored (no trim, exit 0), so the script must whitelist `-e` itself.
- Limitation in v/h mode: the border color is sampled from the image corners, so when the untrimmed edges also carry a border, only the outermost layer on the selected edges is removed (3-layer nested fixture: v stops at 800x1100). Nested bands that span the full width (top/bottom only) peel correctly: 800x1200 to 800x1100 to 800x1000.
- Loop results with fuzz 3%: white border to 600x900 then no shrink; black border to 600x900; 3-layer nested (white 800x1200, gray `#808080` 700x1100, white 660x1060, checkerboard 600x900) to 700x1100, 660x1060, 600x900, then no shrink; flat interior (white 800x1200, solid black 600x900) to 600x900 then 1x1; blank white page to 1x1 with a stderr warning and exit 0.
- A JPEG written at `-quality 87` trims to 600x902 then 600x900. Re-encoding from MIFF without `-quality` gives Q92; with `-quality 87` it gives Q87. An ICC profile and a comment survive the MIFF round trip.
- Writing `UP.PNG` / `UPJ.JPG` (uppercase extensions) gives PNG and JPEG bytes respectively.
- `zparseopts -D -E -F -- f:=opt_f -fuzz:=opt_f e:=opt_e -edges:=opt_e h=opt_h -help=opt_h` parses `-e v`, `--edges h`, `-f5`, and `--fuzz 5`. `--fuzz=5` yields the value `=5`, which the numeric check rejects (same trait as `number-pages.zsh`; help documents the space-separated form). An unknown option makes zparseopts fail, giving exit 1.
- With `trap '...cleanup...' EXIT` plus `trap 'exit 130' INT` / `trap 'exit 143' TERM`, a SIGTERM mid-run still runs the EXIT cleanup.
</design_decisions>
